# RNNoise PyTorch Training with Binary Data

This is a PyTorch implementation of RNNoise training that directly uses binary data generated by `denoise.c`, eliminating the need for HDF5 conversion.

## Features

- **Direct Binary Support**: Uses binary data directly from `denoise.c` output
- **Exact Keras Equivalence**: Matches the original Keras implementation exactly
- **Cross-Platform**: Works on Windows, macOS, and Linux
- **GPU Support**: Automatic CUDA/MPS/CPU detection
- **Weight Constraints**: Implements the same weight clipping as the original

## Quick Start

### 1. Generate Training Data

First, compile and run `denoise.c` to generate binary training data:

```bash
# Compile denoise.c with training support
cd src
gcc -DTRAINING=1 -O3 denoise.c celt_lpc.c kiss_fft.c pitch.c rnn.c rnn_data.c -o denoise_training

# Generate training data (requires clean speech and noise files)
./denoise_training speech.raw noise.raw 100000 > training_data.bin
```

### 2. Test Binary Data Format

```bash
# Test the binary file format
python3 test_binary_format.py --binary-file training_data.bin
```

### 3. Train the Model

```bash
# Basic training
python3 rnn_train_pytorch_new.py --data-file training_data.bin

# Custom parameters
python3 rnn_train_pytorch_new.py \
    --data-file training_data.bin \
    --epochs 120 \
    --batch-size 32 \
    --lr 0.001 \
    --output-model my_model.pth
```

## Command Line Arguments

| Parameter | Default | Description |
|-----------|---------|-------------|
| `--data-file` | `training_10000.f32` | Path to binary training data file |
| `--batch-size` | `32` | Batch size for training |
| `--epochs` | `120` | Number of training epochs |
| `--lr` | `0.001` | Learning rate |

| `--denoise-weight` | `10.0` | Loss weight for denoise output |
| `--vad-weight` | `0.5` | Loss weight for VAD output |

## Model Architecture

The PyTorch implementation exactly matches the original Keras model:

1. **Input Dense Layer**: 42 → 24 neurons, tanh activation
2. **VAD GRU**: 24 hidden units, tanh/sigmoid activations
3. **Noise GRU**: 48 hidden units, ReLU/sigmoid activations
4. **Denoise GRU**: 96 hidden units, tanh/sigmoid activations
5. **Denoise Output**: 96 → 22 neurons, sigmoid activation
6. **VAD Output**: 24 → 1 neuron, sigmoid activation

## Loss Functions

The implementation includes exact PyTorch equivalents of the original Keras loss functions:

- **`mycost`**: Custom denoise loss with complex weighting
- **`my_crossentropy`**: Weighted VAD cross-entropy
- **`msse`**: Mean Squared Square-root Error for metrics
- **`my_accuracy`**: Weighted accuracy metric

## Binary Data Format

The binary format is the direct output from `denoise.c`:

- **Format**: Raw binary float32 data
- **Frame structure**: Each frame contains 87 float32 values:
  - Bytes 0-167: Input features (42 floats)
  - Bytes 168-255: Denoise targets (22 floats)
  - Bytes 256-343: Noise targets (22 floats)
  - Bytes 344-347: VAD target (1 float)
- **Total frame size**: 348 bytes (87 × 4 bytes per float)

## Platform-Specific Notes

### Windows
- Use the modified `denoise.c` that writes directly to files instead of stdout
- This avoids Windows text mode conversion issues with binary data

### macOS/Linux
- Can use either stdout redirection or direct file output
- MPS (Metal Performance Shaders) support for Apple Silicon

### GPU Support
- **CUDA**: NVIDIA GPUs
- **MPS**: Apple Silicon Macs
- **CPU**: Fallback for all systems

## Troubleshooting

### Common Issues

1. **Binary file size not divisible by 87**:
   - Use the modified `denoise.c` that writes directly to files
   - Or use PowerShell on Windows: `program.exe | Out-File -Encoding Byte output.bin`

2. **MPS errors on Apple Silicon**:
   - Use `--device cpu` to force CPU training
   - Or reduce batch size: `--batch-size 16`

3. **CUDA out of memory**:
   - Reduce batch size: `--batch-size 16`
   - Use CPU: `--device cpu`

4. **Data loading errors**:
   - Check binary file format with `test_binary_format.py`
   - Ensure file size is divisible by 348 bytes (87 floats × 4 bytes)

## Differences from Original Keras

While functionally equivalent, the PyTorch version offers:

1. **Direct Binary Support**: No HDF5 conversion needed
2. **Better Cross-Platform**: Handles Windows binary data issues
3. **Modern Framework**: Uses current PyTorch
4. **Flexible Training**: More customizable training loops
5. **Better Debugging**: Easier to inspect model behavior

## Model Conversion

To convert the trained PyTorch model to C-compatible format:

```bash
python3 dump_pytorch_model.py \
    weights.pth \
    rnnoise_weights.c \
    rnnoise_weights.bin \
    --model-name my_model
```

This generates C source code and binary weights for use with the C implementation.
